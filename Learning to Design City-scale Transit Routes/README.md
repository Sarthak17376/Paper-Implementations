# Learning to Design City-Scale Transit Routes (TRNDP)
An Independent Cleanroom Implementation and Production Engineering Framework

## Overview

This repository provides an independent implementation of the Transit Route Network Design Problem (TRNDP) based on the research paper [**"Learning to Design City-scale Transit Routes"**](https://arxiv.org/abs/2512.19767) by Bibek Poudel and Weizi Li ([arXiv:2512.19767](https://arxiv.org/abs/2512.19767), Dec 2025). 

The framework formulates transit network design as an end-to-end sequential decision problem solved using Proximal Policy Optimization (PPO) with a Graph Attention Network v2 (GATv2) policy architecture, validated using the mesoscopic traffic simulator UXsim.

The implementation is cleanroom: no code is imported from the original `AlphaTransit` repository. All algorithms, network architectures, and environment logic are built from first principles using the mathematical specifications in the paper.

## How This Implementation Differs from the Original Paper

While adhering to the theoretical foundation and mathematical formulation of the paper, this repository makes several distinct architectural and engineering contributions:

### 1. Independent Implementation on Public UXsim
The original paper relied on a private, modified fork of UXsim that included a specialized `BusHandler` module. That module is not present in public releases of UXsim (`uxsim==1.14.2`). 

To reproduce the study without proprietary dependencies, this project implements an original **leg-chaining simulation architecture** (`bus_dispatcher.py`) using standard UXsim primitives:
* Bus trips are divided into sequential single-trip `Vehicle` legs with strict route enforcement (`enforce_route`).
* Stop arrivals trigger dynamic `node_event` callbacks to process passenger boarding, alighting, and transfer queues with a calibrated 60-second dwell time.
* The subsequent leg is dynamically scheduled to depart after dwell time expires, ensuring buses interact realistically with competing private car traffic.

### 2. Simulation Clock and Travel Time Accounting
In UXsim, active vehicles continue traveling until they complete their routes, even after the nominal simulation horizon $T_{\text{sim}}$ is reached. A naive implementation that measures travel time against a static $T_{\text{sim}}$ end time produces negative in-vehicle travel times for late boarders. 

In this repository, passenger journey calculations in `finalize_incomplete()` are bound directly to the actual final simulated clock (`W.TIME * W.DELTAT`), ensuring all travel time statistics remain strictly positive and physically accurate.

### 3. Concrete Solutions for Underspecified Details
Where the published text left specific algorithmic details open, principled design choices were implemented and documented:
* **Transit Demand Assignment:** Implemented an exact min-transfers-then-min-time shortest path search across a route-layered state graph (`transit_assignment.py`).
* **Transfer Penalty:** Assigned a 5-minute penalty to transfer edges in the layered graph, ensuring shortest paths prioritize direct connections before travel duration.
* **Route Overlap Metric ($K$):** Bounded the normalization parameter $K$ to the fixed network design budget of 16 routes.
* **Core Node Definition ($V_{\text{core}}$):** Formalized $V_{\text{core}}$ as $V_{\text{cur}} \cup V_{\text{cmp}}$ (the union of the route currently under construction and all finalized routes).

### 4. Production and Cloud Engineering Additions
* **Offline-First Data Pipeline:** Bypasses the Hugging Face client library to stream raw data files directly over HTTPS via standard `urllib`. This eliminates authentication warnings, avoids rate limits, and allows completely offline training.
* **Full-State Checkpointing:** Stores model weights, Adam optimizer states, exact RNG seeds (`torch`, `cuda`, `numpy`, `random`), and training metrics in a format compatible with PyTorch 2.6+ (`weights_only=False`).
* **Kaggle Time Guard:** Implements an automated time check (`--max_hours 11.0`) that cleanly saves checkpoints and terminates before Kaggle's 12-hour session ceiling, allowing training to be chained across multiple runs.
* **Fast Route Extraction:** Provides a utility (`generate_routes_from_checkpoint`) to extract route geometries from any checkpoint in roughly 2 seconds without running full mesoscopic traffic simulations.

## Methodological Summary

### Problem Setting
The TRNDP is modeled as a finite-horizon Markov Decision Process $(S, A, P, R, \gamma)$ on an undirected road network graph $G = (V, E)$ for Bloomington, Indiana:
* **Nodes:** 143 intersections and transit stops
* **Edges:** 243 bidirectional road segments (486 directed links)
* **Design Budget:** Exactly $K = 16$ routes
* **Route Length Limits:** $L_{\min} = 2$, $L_{\max} = 14$ nodes per route
* **Demand Matrix:** 5,737 Origin-Destination pairs derived from US Census LODES data

### State and Action Space
* **State ($s_t$):** Includes 16-dimensional node features (coordinates, degree, OD marginals, and candidate/core demand metrics), edge indices, and edge features (length and free-flow speed).
* **Action ($a_t$):** Sequential selection of the next adjacent stop. An action mask restricts the distribution to valid, unvisited 1-hop neighbors ($C_t$), ensuring all routes are self-avoiding simple walks.

### Two-Level Reward Function
To address sparse rewards across long horizons ($T = 224$ steps per episode), feedback is provided at two granularities:
* **Intermediate Topological Reward ($|r_k| < L_{\max}$):**
  $$R_{\text{partial}}(s_t, a_t) = \beta_0 \Psi - \beta_1 \omega - \beta_2 \left(1 - \frac{|r_k|}{L_{\max}}\right)$$
  where $\Psi$ measures demand coverage potential and $\omega$ measures route overlap depth across shared edges ($\beta_0 = 40, \beta_1 = 20, \beta_2 = 15$).
* **Terminal Simulation Reward ($|r_k| = L_{\max}$):**
  $$R_{\text{final}}(s_t, a_t) = \beta_3 \Psi + \beta_4 \sigma - \beta_5 \tau - \beta_6 \omega$$
  where $\sigma$ is the simulation service rate ($N_{\text{boarded}} / N_{\text{want}}$) and $\tau$ is normalized average travel time ($\beta_3 = 30, \beta_4 = 15, \beta_5 = 15, \beta_6 = 10$).

### Frequency of Service (FOS)
Post-design frequencies are computed deterministically using the maximum-load principle:
$$F_k = \left\lceil \frac{Q_{k,\max}^{\text{norm}}}{\delta_{\max} \cdot C_k} \right\rceil$$
with comfort threshold $\delta_{\max} = 0.8$ and bus capacity $C_k = 40$.

## Quickstart

### 1. Installation
```bash
pip install torch torch-geometric gymnasium uxsim plotly matplotlib pandas numpy
```

### 2. Download Dataset
The dataset can be cached locally without external API tokens:
```python
import os, urllib.request

os.makedirs("./data", exist_ok=True)
BASE_URL = "https://huggingface.co/datasets/matrix-multiply/bloomington-tndp/resolve/main/standard"

files = [
    ("bloomington_nodes_standard.csv", "bloomington_nodes.csv"),
    ("bloomington_links_standard.csv", "bloomington_links.csv"),
    ("bloomington_demand_standard.csv", "bloomington_demand.csv"),
    ("bloomington_existing_routes.json", "bloomington_routes.json"),
]

for remote, local in files:
    urllib.request.urlretrieve(f"{BASE_URL}/{remote}", f"./data/{local}")
```

### 3. Running Training

**Quick verification run (2 episodes):**
```bash
python train.py --data_source csv --num_routes 2 --max_route_length 5 --t_sim 1000 --num_episodes 2 --rollout_steps 32 --save_every 1 --checkpoint_dir ./test_checkpoints
```

**Full production training (200 episodes):**
```bash
python train.py \
  --data_source csv \
  --num_routes 16 \
  --max_route_length 14 \
  --t_sim 10000 \
  --num_episodes 200 \
  --save_every 5 \
  --max_hours 11.0 \
  --checkpoint_dir ./checkpoints \
  --device cuda
```

**Resuming an interrupted run:**
```bash
python train.py \
  --data_source csv \
  --resume ./checkpoints/checkpoint_latest.pt \
  --num_episodes 200 \
  --save_every 5 \
  --device cuda
```
